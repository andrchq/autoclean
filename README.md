# Server cleanup

`cleanup-server.sh` — консервативный Bash-скрипт для Linux-сервера. При запуске без аргументов он очищает терминал и открывает интерактивное меню: стрелками выбирается режим, Enter подтверждает выбор.

## Что он делает

- чистит кеши пакетных менеджеров и оставляет systemd journal не старше 7 дней;
- удаляет crash dumps, а также файлы в `/tmp` и `/var/tmp` старше 7 дней;
- удаляет старые ротации из `/var/log`, но не трогает активные логи;
- показывает крупнейшие файлы на корневом разделе, ничего из отчёта автоматически не удаляя.

Docker, удаление неиспользуемых пакетов, volumes и обнуление крупных активных логов выключены, пока не передать соответствующий флаг. Скрипт не обходит `/home`, каталоги приложений и подключённые диски.

## Интерактивный режим

```text
Аудит сервера    фоново просчитывает количество и общий объём безопасных
                 кандидатов на удаление, не печатая имена отдельных файлов.

Очистка сервера  открывает экран с чекбоксами. Стрелками выбирается строка,
                 Enter включает/выключает её; на «Начать очистку» запускается
                 только выбранное.

Автоочистка      создаёт и изменяет задачи по расписанию через systemd timers.
                 Каждая задача хранит собственное расписание и набор действий.

Выход            завершает работу и оставляет на экране фирменную шапку.
```

В интерактивном режиме включены только безопасные пункты: кеши, journal, crash dumps, старые tmp-файлы и старые ротации логов. Docker, volumes, autoremove и обнуление активных логов выключены по умолчанию.

После аудита или очистки результат остаётся на экране до Enter. Затем скрипт возвращает в главное меню и показывает последнее выполненное действие с его счётчиками.

Во всех подменю есть приглушённая кнопка «Назад». В главном меню её роль выполняет «Выход»: после подтверждения остаётся фирменная шапка и пожелание хорошего дня.

Во время интерактивной очистки терминал не заполняется выводом `apt`, Docker и других команд: отображается только спиннер с общим таймером. Если отдельная операция не выполнится, её технический вывод будет сохранён в закрытом логе вида `/tmp/autoclean-errors-YYYYMMDD-HHMMSS-PID.log`.

## Автоочистка

Откройте `cll`, выберите «Автоочистка» и настройте одну или несколько независимых задач:

- каждый день — одно время запуска;
- по дням недели — один или несколько отмеченных дней и время;
- по числам месяца — числа от 1 до 31 через запятую и время. Если выбранного числа нет в коротком месяце, этот запуск пропускается.

Время можно вводить как `03:30`, `0330`, `03 30`, `03,30` или `03.30`. Перед сохранением скрипт показывает итоговое расписание, часовой пояс сервера и выбранные действия очистки. Чтобы запускать очистку несколько раз в сутки, создайте несколько задач.

Сохранённые задачи показываются списком. Каждую из них можно изменить с предварительно заполненными значениями или удалить после отдельного подтверждения. Для расписаний нужен запущенный `systemd`; если его нет, скрипт вернётся в меню и ничего не создаст.

Конфигурации находятся в `/etc/autoclean/tasks/<id>.conf`, а таймеры — в `/etc/systemd/system/autoclean-<id>.timer`. Каталог конфигураций создаётся с правами `0700`, файлы — `0600`. Перед каждым автоматическим запуском команда `cll` проверяет обновление, затем выполняет только сохранённые действия. `Persistent=true` запускает один пропущенный сеанс после следующего включения сервера.

## Установка и запуск

Первый запуск — одна команда. Она установит скрипт как `/usr/local/bin/cll`:

```bash
curl -fsSL "https://raw.githubusercontent.com/andrchq/autoclean/main/cleanup-server.sh?ts=$(date +%s)" | sudo bash
```

После этого всегда запускайте его так:

```bash
cll
```

Если нужны права root, `cll` сам запросит пароль sudo. При каждом запуске он проверяет новую версию в GitHub. Если она есть, команда автоматически обновляет файл и перезапускается уже на новой версии. `ts=$(date +%s)` в первой команде предотвращает выдачу старой копии из кеша GitHub CDN.

Для аудита или автоматического запуска используйте `cll` с параметрами:

```bash
# Аудит без меню: ничего не меняет
cll --audit

# Стандартная очистка
cll --yes

# Очистка Docker (без volumes)
cll --yes --docker
```

Перед первым реальным запуском обязательно выполните аудит и просмотрите вывод.

## Дополнительные флаги

```text
--docker                      чистит stopped containers, dangling images,
                              networks и build cache
--docker-volumes              удаляет неиспользуемые volumes; требует --docker
--autoremove                  удаляет неиспользуемые пакеты
--truncate-logs               обнуляет активные логи в /var/log только если
                              размер превышает заданный порог
--active-log-min-size 250M    меняет порог активных логов
--tmp-age-days 14             меняет срок хранения файлов во временных папках
--journal-max-age 14d         меняет срок хранения journal
--rotated-log-age-days 30     меняет срок хранения ротаций логов
--min-large-size 1G           меняет порог отчёта о больших файлах
```

Подробная справка доступна так:

```bash
cll --help
```

## Важное ограничение

Скрипт предназначен для систем с GNU userland — Ubuntu/Debian, RHEL/Fedora, Rocky/AlmaLinux и похожих. Не запускайте его вслепую на production-сервере: сначала dry-run, затем очистка без дополнительных агрессивных флагов.
